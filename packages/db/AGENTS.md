# @multitudes/db

Drizzle schema, every SQL query, both migration journals, the pg-boss queue, and
test-database lifecycle. Every runtime workspace imports it through subpath exports.

## File tree

```text
packages/db/
├── src/
│   ├── auth-schema.ts       # Better Auth tables, generated by `pnpm auth:generate` (core)
│   ├── post-schema.ts       # unused template `post` table, kept to avoid a destructive migration (core)
│   ├── agent-schema.ts      # runs, events, evals, model_call ledger, submissions (agents)
│   ├── schema.ts            # re-exports all three schemas
│   ├── client.ts            # process-wide pg pool and drizzle `db`
│   ├── queue.ts             # pg-boss singleton and `agent-run` queue policy
│   ├── runs.ts              # enqueue, attempt fencing, session store, reconciler, reads
│   ├── agent-service.ts     # actor-scoped task service shared by tRPC and agent tools
│   ├── usage.ts             # model_call ledger start/finish
│   ├── dashboard.ts         # Studio /admin aggregates
│   ├── migrate.ts           # core then agents journals under one advisory lock
│   ├── testing.ts           # createTestDatabase(): unique migrated DB, dropped on close
│   └── index.ts             # drizzle-orm/sql operators and `alias`
├── migrations/
│   ├── core/                # journal table drizzle.core_migrations
│   └── agents/              # journal table drizzle.agent_migrations
├── script/migrate.ts        # `pnpm db:migrate` entry
├── drizzle.core.config.ts   # generate config: auth + post schemas
├── drizzle.agents.config.ts # generate config: agent schema
└── drizzle.config.ts        # db:push / db:studio only, no journal
```

## Conventions

- A table's schema file decides its journal: auth and template tables live in
  `auth-schema.ts`/`post-schema.ts` (core); everything agent or eval lives in
  `agent-schema.ts` (agents). `pnpm db:generate` runs both configs; commit the new
  SQL with its `meta/` snapshot and journal entry, and add new migrations rather
  than editing applied ones.
- `auth-schema.ts` is generated output. Change Better Auth options in
  `packages/auth`, run `pnpm auth:generate`, then `pnpm db:generate`.
- pg-boss creates and migrates its own `pgboss` schema at startup; it belongs to
  neither journal.
- Write camelCase in TypeScript; columns are snake_case. Every drizzle instance,
  including one wrapping a raw transaction client, passes `casing: "snake_case"`.
- Runs and their queue jobs commit together: `enqueueRuns` hands its transaction
  client to `queue.send` through `db.executeSql`. Any new job producer follows the
  same pattern so a job never exists without its row (or the reverse).
- Admission receipts: `submission` is unique on `(owner_id, key)`. A repeated key
  returns the original run IDs; a different fingerprint under the same key throws.
- Run-attempt writes go through `withAttempt(runId, attempt, fn)`, which row-locks
  the run and throws `Run attempt superseded` for stale workers. `finishModelCall`
  is intentionally unfenced so real spend is recorded even for superseded attempts.
- Services such as `agent-service.ts` receive the actor ID from the trusted caller
  and take an injectable lookup so eval fixtures reuse the same validation. The
  harness section of `docs/agent-platform.md` names `packages/api/src/agent-service.ts`;
  the service lives here.
- `client.ts` and `queue.ts` cache their singletons on `globalThis` to survive
  Next.js dev reloads. Import them only from server code.
- A new module needs a subpath in `package.json` `exports` with both `types`
  (`dist/*.d.ts`) and `default` (`src/*.ts`) entries.
- Verify schema or query changes with
  `TEST_POSTGRES_URL=... pnpm -F @multitudes/db test:integration` against a
  disposable server (see `docs/development.md`).
